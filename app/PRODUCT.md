# ApplyFolio

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

参加校招的个人求职者，使用桌面与手机记录投递、跟进招聘进度，并查阅笔试和面试题目。

## Product Purpose

辅助投递：从找岗位开始，收录岗位意向时顺手拿到 AI 简历建议，投出后把进度写进同一本投递簿。以公司与岗位为单位保留记录，让每次投递的进度、网址、岗位要求、题目文字和截图能够集中查找。

## Operating Context

已有 React / Vite / TypeScript 工程。邮箱密码登录，Supabase 存储与多设备同步，可安装为 PWA。
主路径为登录或注册 → 欢迎层 → 投递簿 → 点主按钮「投递」进居中的「找岗位」面板（输企业名 → 按匹配度列出候选官网，点哪条进哪条、回车进第一条，没命中才用搜索引擎 → 新标签浏览 → 扩展就地收录或把岗位页网址粘回来由服务端抓取 → 确认收录并分析）→ 列表点「已投出」进入初筛；投递详情/编辑抽屉含题目与简历建议；账号页位于 /me（自我评价、简历上传）。

## Capabilities and Constraints

- 搜索、状态多选、排序、公司分组折叠、每页 15 家公司、记录置顶与自由颜色标识。
- 同一公司多个岗位仍为独立记录。招聘状态与标签以 src/db/schema.ts 为单一来源。
- 编辑抽屉保留题目/备注、简历建议与编辑信息三个标签页，题目支持文字与图片。
- 「找岗位」只通向**企业自己的校园招聘官网**：内置 32 家企业校招官网直达（地址实测可达），按输入的企业名打分排序（名称一致 / 别名 / 前缀 / 包含），回车或点击直接进入；一条都没命中才退回搜索引擎（查询固定拼「{企业} 校园招聘 官网」）。**不接招聘软件**（BOSS直聘 / 猎聘 / 前程无忧 / 智联）。
- 「找岗位」只能把用户送到外部站（新标签），不得尝试 iframe 内嵌：招聘站普遍用 X-Frame-Options / CSP 禁止被嵌，且跨域 iframe 读不到 DOM（能显示≠能读取）。
- 岗位信息（公司 / 岗位 / 岗位要求）优先由**浏览器扩展**在岗位页就地提取（v3.2 起，`app/extension/`，MV3 未打包；v3.3 起 v0.2.0）：校招官网首屏是 SPA 空壳，服务端拿到 HTML 里根本没有岗位文字。默认权限只有 `activeTab` + `scripting` + `contextMenus`，内置 32 家靠 `content_scripts` 白名单自动注入，其它站点由图标 / `Alt+Shift+A` / 右键菜单触发；「全站自动」做成可选授权（`optional_host_permissions`），不得默认申请宽权限。提取结果压成 `#import=<token>` 交给应用预填，数据不经过任何服务器。
- 服务端抓取（Edge Function 的 `scrape` 动作）保留为「手动粘网址」路径；扩展与服务端都拿不到时，用剪贴板读取整页文字兜底。
- AI 简历建议由 Supabase Edge Function（analyze-job）+ DeepSeek 生成，密钥只在服务端；未配置或失败时必须降级为「只收录」，不得阻断主流程。
- 简历存私有桶 resumes，PDF/TXT/MD 抽取文字；扫描版 PDF 用手填文本兜底，文本优先于原件。
- 不增加自动投递/代填表单、数据看板或协作模块。

## Product Principles

- 先让投递进度、公司与岗位易于扫描，再安排艺术表现。
- 保留明确的新增、编辑、筛选和查看题目入口。
- 真实数据与演示数据保持区别，统计从记录计算。
- 桌面与手机都能完成核心操作，键盘焦点可见且可回归。
