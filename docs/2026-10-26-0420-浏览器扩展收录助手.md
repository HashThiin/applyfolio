# 浏览器扩展收录助手（v3.2）

> 2026-10-26 04:20。回应两点：①抓取应该是「应用内」完成的，不该让用户把网址粘回来；②只去校招官网的前提下，能不能直接把官网 iframe 内嵌进来。
>
> 结论先说：**不能内嵌（技术读不到 + 法律不当然允许）**，正确做法是 **在岗位页里就地提取，再把结果送回应用** —— 已实现为未打包的 MV3 扩展，`app/extension/`。

## 一、为什么不是 iframe

### 1. 技术上：能看见 ≠ 能读到

同源策略按 **origin（协议 + 域名 + 端口）** 划分。跨域 iframe 里 `contentDocument` 为 `null`（或抛 SecurityError），拿不到任何 DOM 节点、文字、甚至真实高度。对方没有配合挂 `postMessage`，内嵌就只是个黑盒画框：用户看得见，程序读不到。

`X-Frame-Options` / CSP `frame-ancestors` 只决定**能不能显示**，与能不能读是两套机制 —— 别把「对方没设头」误当成「可以抓」。

实测 12 家校招官网响应头（2026-10-26）：

| 站点 | `X-Frame-Options` | CSP `frame-ancestors` | 内嵌能否显示 |
|---|---|---|---|
| 字节 `jobs.bytedance.com` | `SAMEORIGIN` | 未设 | 否 |
| 阿里 `talent.alibaba.com` | `SAMEORIGIN` | 未设 | 否 |
| 百度 `talent.baidu.com` | `SAMEORIGIN` | `'self'` | 否 |
| 其余 9 家（腾讯/华为/美团/京东/网易/小米/拼多多/快手/B站 等） | 未设 | 未设 | 是（但读不到内容，且随时可能加上） |

### 2. 首屏 HTML 也证明服务端抓不到

对同一批 12 个官网首页做 `Invoke-WebRequest`，看服务端拿到的东西：

- `htmlLen` 区间 **607 – 67,945** 字节，**「岗位」二字出现 0 次**
- **0 家**有 JSON-LD `JobPosting`
- 基本是 `#app` / `#root` 的 SPA 空壳（拼多多是 `__NEXT_DATA__`）

也就是说 v3.1 的 Edge Function `scrape`（按 JSON-LD → og → 正文顺序抓）对这些官网列表页本来就没戏。原因不是抓得不好，而是**岗位内容在浏览器渲染后才存在**。

### 3. 法律上：内嵌不构成当然合法

「公开可访问」不等于「可任意复制展示」：

- **著作权**：JD 文本、企业介绍属于文字作品。内嵌后在自己产品里呈现，是否落进《著作权法》第 24 条「适当引用（为介绍、评论或说明问题）」要按**目的、数量、是否影响原作使用**逐案判断；整站深度内嵌基本站不住。
- **反不正当竞争**：《反不正当竞争法》第十二条针对以技术手段妨碍、破坏他人产品正常运行；若内嵌到「实质性替代原站」的程度，风险显著上升。
- **合同与标识**：各站服务条款普遍禁止未授权抓取/镜像；内嵌还会抹掉对方的品牌与广告位。
- **实际风险随规模变化**：个人自用几乎无人追究，一旦对外分发/上线成产品，性质和责任完全不同。具体定性请咨询律师。

> 所以「合法内嵌」这个前提本身不成立，绕开它的办法不是更强的抓取，而是**换执行位置**：让代码跑在用户的浏览器里、在用户自己已经打开的页面上工作 —— 这正是扩展。

## 二、落地方式：MV3 扩展（未打包，开发者模式加载）

### 为什么是扩展而不是书签脚本

书签 `javascript:` 在现代浏览器被 CSP（`script-src` 不含 `unsafe-inline`）大量拦死，且拿不到 `chrome.*` API。扩展有 `activeTab` + `scripting`，能在**用户主动触发**时读写当前页，权限最小、无需常驻 host 权限。

### 数据怎么回到应用

不经过任何服务器：

```
岗位页 --(content script 提取)--> {company, role, jdText, url}
      --(base64url(gzip(JSON)))--> #import=<token>
      --window.open--> https://applyfolio-silk.vercel.app/#import=<token>
```

- **hash 不发服务器**：不进 HTTP 请求行、不进 Vercel 访问日志
- **首帧中转**：`main.tsx` 在 React 渲染前把 token 挪进 `sessionStorage` 并 `history.replaceState` 抹掉 hash（地址栏干净、刷新不重复导入）
- **登录跳转不丢**：未登录时 AuthGuard 跳 `/login`，token 留在 sessionStorage，登录后 `MainApp` 取出解码、打开面板并预填
- **压缩**：JD 上千字时 token 会很长，用 `CompressionStream('gzip')`；超 12000 字符就逐级砍 JD（4000 → 2000 → 1500 字）

### 提取顺序（`extension/extract.js`）

1. JSON-LD `JobPosting`（有就是最准的，`description` 走 `DOMParser` 去标签，避免 detached `innerHTML` 真去加载 `<img>`）
2. 站点规则（`extension/sites.js` 里 12 家各写一组候选选择器，取第一个命中的）
3. `og:title` / `document.title`（按 `-`、`|`、`_` 切分，识别「岗位—公司」还是「公司—岗位」）
4. 兜底：正文里最大文本块（≥120 字，上限 12000 字）

### 交互

点工具栏图标或（12 家站点上）页面加载后自动注入 → 右下角 Shadow DOM 卡片（`all: initial` + 独立 `<style>`，站点 CSS 打不进来）→ 可改公司/岗位/JD → 「收录到 ApplyFolio」新标签打开应用并预填 → 应用内的「找岗位」面板出现提示条，核对后点「收录并分析」。

提取不出内容时不会静默失败：卡片给「没读到内容：这是列表页吗？进具体岗位详情页再试」，并留「复制」按钮把 JSON 贴出来排查。

## 三、改了哪些文件

**新增**

| 文件 | 作用 |
|---|---|
| `extension/manifest.json` | MV3；`permissions: ["activeTab","scripting"]`；12 家 `content_scripts`（`sites → extract → encode → panel` 顺序敏感） |
| `extension/sites.js` | 12 家 host → `{name, company, role[], jd[]}`，公司名按域名兜底 |
| `extension/extract.js` | 提取与清洗，导出 `globalThis.AF_EXTRACT` |
| `extension/encode.js` | `base64url(gzip(json))`，必须与 `src/lib/jobImport.ts` 完全一致 |
| `extension/panel.js` | Shadow DOM 卡片，全 `createElement`/`textContent`，无 `innerHTML` |
| `extension/background.js` | `chrome.action.onClicked` → `scripting.executeScript` 注入四个文件（兜住 12 家以外的站点） |
| `extension/icons/` | 复用 PWA 的 192/512 图标 |
| `src/lib/jobImport.ts` | `ImportedJob` 类型、编解码、`captureImportFromHash`、`consumePendingImport`、`sanitizeImportedJob` |
| `src/test/jobImport.test.ts` | 10 条用例（往返、压缩、坏 token、越界字段、hash 解析、StrictMode 重复消费） |

**修改**

| 文件 | 改动 |
|---|---|
| `src/main.tsx` | `createRoot` 前调 `captureImportFromHash()` |
| `src/features/MainApp.tsx` | 新增 `importedJob` state + 消费 effect；面板 `onClose` 同时清空 |
| `src/features/intents/IntentPanel.tsx` | 新增 `imported` prop 与预填 effect（`appliedImport` ref 防重复覆盖用户手改）；第 ② 段加「装了扩展」折叠说明 |

## 四、安装（不需要商店，2 分钟）

1. `chrome://extensions` → 右上「开发者模式」打开
2. 「加载已解压的扩展程序」→ 选 `d:\job\app\extension`（部署到别的机器就把这个目录一起拷过去）
3. 打开任一校招岗位详情页 → 右下角出现卡片；其它站点点工具栏图标也能唤出
4. 改完公司/岗位 → 「收录到 ApplyFolio」→ 新标签打开应用，核对后点「收录并分析」

> 本地调试：把 `extension/panel.js` 顶部的 `APP_ORIGIN` 改成 `http://localhost:5173` 重载扩展。

## 五、已知边界

- **12 家选择器是候选列表，未逐站真机校准**。官网改版后可能退回「正文最大块」，此时 JD 会带导航/页脚噪声 —— 首次使用请用卡片里的「复制」核对一次，或者直接把 JD 手工修一下再收录（表单本来就是可改的）。
- **详情页优先**：列表页提取不到岗位信息是设计使然（列表页没有单一岗位）。
- **只能跑在 Chromium**（Chrome/Edge）。Firefox 需改 `background.scripts`、Safari 需 Xcode 打包，暂不做。
- **上架商店**是另一件事：要审核、要隐私政策、要向用户解释「读取当前页」的用途；当前是个人自用，不进商店。
- **不替代服务端抓取**：v3.1 的 `scrape` 仍保留，用于「用户手动粘网址」的兜底路径（对少数服务端渲染的页面依然有效）。
