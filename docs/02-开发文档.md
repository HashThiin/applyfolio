## 1. 技术选型

### 1.1 为什么从 Next.js 改为 Vite

需求收敛为纯前端 CRUD 后，原先的 Next.js + SQLite 方案属于明显过度设计：

| 对比项 | Next.js + SQLite | **Vite + IndexedDB（选用）** |
| --- | --- | --- |
| 数据位置 | 本地 `.db` 文件 | 浏览器 IndexedDB |
| 启动方式 | 需常驻 Node 服务 | 开发时 `npm run dev`，构建后可静态托管 |
| 依赖体积 | 约 300MB | 约 60MB |
| 首个页面加载 | 需服务端渲染链路 | 纯静态，毫秒级 |
| 加 LLM 能力 | 天然支持 | 需引入后端（V2 再迁） |

结论：V1 用 **Vite + React + IndexedDB**，代码量约为 Next.js 方案的三分之一，且不需要跑服务端进程。若未来恢复 AI 匹配能力，按 01 文档 V2.0 的路径迁移即可。

### 1.2 技术栈

| 层 | 选型 | 版本 | 理由 |
| --- | --- | --- | --- |
| 构建 | Vite | 7.x | 冷启动快，配置少 |
| 框架 | React | 19.x | 生态成熟 |
| 语言 | TypeScript | 5.x | `strict: true`，字段类型与需求表一一对应 |
| 样式 | Tailwind CSS | 4.x | 无需写 CSS 文件，通过 `@tailwindcss/vite` 插件接入 |
| 数据库 | Dexie | 4.x | IndexedDB 的类型化封装，支持索引与事务 |
| 响应式查询 | dexie-react-hooks | 4.x | `useLiveQuery` 让 UI 随数据自动刷新，省掉状态管理库 |
| 图标 | lucide-react | latest | 按需 tree-shaking，体积小 |
| 表单 | 原生受控组件 | — | 7 个字段，引入 react-hook-form 反而增加心智负担 |
| 状态管理 | 无 | — | 数据源唯一（Dexie），UI 状态用 `useState` 足够 |
| 测试 | Vitest | 3.x | 只测纯函数与导入导出逻辑 |

**明确不引入**：Redux / Zustand / TanStack Query / UI 组件库 / 路由库（单页无需路由）。

## 4. 数据层实现

### 4.1 类型定义 `src/db/schema.ts`

```ts
export const STATUSES = [
  { value: "applied", label: "已投递", tone: "blue" },
  { value: "written", label: "笔试", tone: "violet" },
  { value: "interview", label: "面试", tone: "amber" },
  { value: "offer", label: "已 Offer", tone: "emerald" },
  { value: "rejected", label: "已挂", tone: "slate" },
  { value: "withdrawn", label: "已放弃", tone: "slate" },
] as const;

export type ApplicationStatus = (typeof STATUSES)[number]["value"];

export const STATUS_LABEL: Record<ApplicationStatus, string> = Object.fromEntries(
  STATUSES.map((s) => [s.value, s.label]),
) as Record<ApplicationStatus, string>;

export const CHANNELS = [
  "官网",
  "内推",
  "BOSS直聘",
  "牛客",
  "实习僧",
  "校园宣讲",
  "其他",
] as const;

export type Channel = (typeof CHANNELS)[number];

export interface Application {
  id: string;
  company: string;
  role: string;
  url?: string;
  appliedAt: string; // YYYY-MM-DD
  status: ApplicationStatus;
  channel?: Channel;
  note?: string;
  createdAt: number;
  updatedAt: number;
}

/** 新建时的入参：id 与时间戳由仓储层生成 */
export type ApplicationInput = Omit<Application, "id" | "createdAt" | "updatedAt">;

export const TERMINAL_STATUSES: ApplicationStatus[] = ["offer", "rejected", "withdrawn"];
```

> 使用 `as const` 派生联合类型的写法，保证枚举值与展示文案永远同步；新增状态只需改 `STATUSES` 一处。

### 4.2 Dexie 实例 `src/db/index.ts`

```ts
import Dexie, { type Table } from "dexie";
import type { Application } from "./schema";

class JobCompassDB extends Dexie {
  applications!: Table<Application, string>;

  constructor() {
    super("job-compass");
    this.version(1).stores({
      // 主键 id；其余为索引字段。
      // company / role / note 不建索引，采用内存过滤（数据量 ≤ 1000，无需全文索引）
      applications: "id, company, status, appliedAt, updatedAt, createdAt",
    });
  }
}

export const db = new JobCompassDB();

export async function createApplication(input: Omit<Application, "id" | "createdAt" | "updatedAt">) {
  const now = Date.now();
  const record: Application = {
    ...input,
    id: crypto.randomUUID(),
    createdAt: now,
    updatedAt: now,
  };
  await db.applications.add(record);
  return record;
}

export async function updateApplication(id: string, patch: Partial<Application>) {
  await db.applications.update(id, { ...patch, updatedAt: Date.now() });
}

export async function deleteApplication(id: string) {
  await db.applications.delete(id);
}

/** 用于撤销删除：原样 put 回去，保留原 id 与时间戳 */
export async function restoreApplication(record: Application) {
  await db.applications.put(record);
}
```

### 4.3 响应式查询 `src/features/applications/useApplications.ts`

```ts
import { useLiveQuery } from "dexie-react-hooks";
import { db } from "@/db";
import type { ApplicationStatus } from "@/db/schema";

export interface Query {
  keyword: string;
  statuses: ApplicationStatus[]; // 空数组表示全部
  sortBy: "appliedAt" | "company" | "updatedAt";
}

export function useApplications(query: Query) {
  return useLiveQuery(async () => {
    const all = await db.applications.toArray();
    const kw = query.keyword.trim().toLowerCase();

    let rows = all.filter((r) => {
      const statusOk = query.statuses.length === 0 || query.statuses.includes(r.status);
      if (!statusOk) return false;
      if (!kw) return true;
      return (
        r.company.toLowerCase().includes(kw) ||
        r.role.toLowerCase().includes(kw) ||
        (r.note ?? "").toLowerCase().includes(kw)
      );
    });

    rows = rows.sort((a, b) => {
      if (query.sortBy === "company") return a.company.localeCompare(b.company, "zh-CN");
      if (query.sortBy === "updatedAt") return b.updatedAt - a.updatedAt;
      // 默认按投递日期倒序；同日用 createdAt 保证顺序稳定
      return b.appliedAt.localeCompare(a.appliedAt) || b.createdAt - a.createdAt;
    });

    return rows;
  }, [query.keyword, query.statuses.join(","), query.sortBy]);
}
```

> `useLiveQuery` 的依赖数组用 `query.statuses.join(",")` 而非数组本身，避免每次渲染因引用变化触发重复查询。

## 5. 核心工具函数

### 5.1 网址处理 `src/lib/url.ts`

```ts
/** 规范化用户输入的网址：补协议、校验合法性。非法返回 null */
export function normalizeUrl(input: string): string | null {
  const raw = input.trim();
  if (!raw) return null;

  const withScheme = /^https?:\/\//i.test(raw) ? raw : `https://${raw}`;
  try {
    const u = new URL(withScheme);
    // 拒绝 "abc" 这类被解析成 hostname 的裸词
    if (!u.hostname.includes(".")) return null;
    return u.toString();
  } catch {
    return null;
  }
}

/** 提取用于展示的域名，如 jobs.bytedance.com */
export function hostOf(url?: string): string {
  if (!url) return "";
  try {
    return new URL(url).hostname.replace(/^www\./, "");
  } catch {
    return "";
  }
}

export function isSafeHttpUrl(url: string): boolean {
  try {
    const u = new URL(url);
    return u.protocol === "http:" || u.protocol === "https:";
  } catch {
    return false;
  }
}
```

### 5.2 CSV 导出 `src/lib/csv.ts`

```ts
import { STATUS_LABEL, type Application } from "@/db/schema";

const HEADERS = ["公司", "岗位", "网址", "投递日期", "状态", "渠道", "备注"];

function escapeCell(value: string | undefined): string {
  const s = (value ?? "").replace(/\r?\n/g, " ");
  return /[",\n]/.test(s) ? `"${s.replace(/"/g, '""')}"` : s;
}

export function toCsv(rows: Application[]): string {
  const lines = [HEADERS.join(",")];
  for (const r of rows) {
    lines.push(
      [
        r.company,
        r.role,
        r.url ?? "",
        r.appliedAt,
        STATUS_LABEL[r.status],
        r.channel ?? "",
        r.note ?? "",
      ]
        .map(escapeCell)
        .join(","),
    );
  }
  // BOM：Excel 直接双击打开时中文不乱码
  return "\uFEFF" + lines.join("\r\n");
}

export function downloadFile(filename: string, content: string, mime: string) {
  const blob = new Blob([content], { type: mime });
  const objectUrl = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = objectUrl;
  a.download = filename;
  a.rel = "noopener";
  a.click();
  URL.revokeObjectURL(objectUrl);
}

export function todayStamp(): string {
  const d = new Date();
  const p = (n: number) => String(n).padStart(2, "0");
  return `${d.getFullYear()}${p(d.getMonth() + 1)}${p(d.getDate())}`;
}
```

> 必须用 `\r\n` 换行并加 BOM，否则 Windows 版 Excel 打开会整行挤在一起。

### 5.3 备份与恢复 `src/db/backup.ts`

```ts
import { db } from "./index";
import type { Application } from "./schema";

const APP_TAG = "job-compass";
const CURRENT_VERSION = 1;

export interface BackupFile {
  app: string;
  version: number;
  exportedAt: string;
  count: number;
  applications: Application[];
}

export async function buildBackup(): Promise<BackupFile> {
  const applications = await db.applications.toArray();
  return {
    app: APP_TAG,
    version: CURRENT_VERSION,
    exportedAt: new Date().toISOString(),
    count: applications.length,
    applications,
  };
}

export type ImportMode = "merge" | "replace";

export interface ImportPreview {
  toAdd: number;
  toUpdate: number;
  toSkip: number;
  records: Application[];
}

export class ImportError extends Error {}

const REQUIRED_KEYS = ["id", "company", "role", "appliedAt", "status"] as const;

function assertIsApplication(value: unknown, index: number): asserts value is Application {
  if (typeof value !== "object" || value === null) {
    throw new ImportError(`第 ${index + 1} 条记录不是对象`);
  }
  const v = value as Record<string, unknown>;
  for (const key of REQUIRED_KEYS) {
    if (typeof v[key] !== "string" || !(v[key] as string).trim()) {
      throw new ImportError(`第 ${index + 1} 条记录缺少字段 ${key}`);
    }
  }
}

export function parseBackup(text: string): BackupFile {
  let json: unknown;
  try {
    json = JSON.parse(text);
  } catch {
    throw new ImportError("文件不是合法的 JSON");
  }
  const data = json as Partial<BackupFile>;
  if (data.app !== APP_TAG) throw new ImportError("这不是 JobCompass 的备份文件");
  if (data.version !== CURRENT_VERSION) {
    throw new ImportError(`备份版本 ${data.version} 与当前版本 ${CURRENT_VERSION} 不兼容`);
  }
  if (!Array.isArray(data.applications)) throw new ImportError("备份文件缺少 applications 数组");
  data.applications.forEach(assertIsApplication);
  return data as BackupFile;
}

/** 只计算差异，不落库，用于导入前的预览弹窗 */
export async function previewImport(file: BackupFile): Promise<ImportPreview> {
  const existing = new Map((await db.applications.toArray()).map((r) => [r.id, r]));
  let toAdd = 0;
  let toUpdate = 0;
  let toSkip = 0;

  for (const rec of file.applications) {
    const old = existing.get(rec.id);
    if (!old) toAdd += 1;
    else if ((rec.updatedAt ?? 0) > old.updatedAt) toUpdate += 1;
    else toSkip += 1;
  }
  return { toAdd, toUpdate, toSkip, records: file.applications };
}

export async function applyImport(
  file: BackupFile,
  mode: ImportMode,
): Promise<{ added: number; updated: number }> {
  const records = file.applications.map((r) => ({
    ...r,
    createdAt: r.createdAt ?? Date.now(),
    updatedAt: r.updatedAt ?? Date.now(),
  }));

  if (mode === "replace") {
    await db.transaction("rw", db.applications, async () => {
      await db.applications.clear();
      await db.applications.bulkPut(records);
    });
    return { added: records.length, updated: 0 };
  }

  let added = 0;
  let updated = 0;
  await db.transaction("rw", db.applications, async () => {
    for (const rec of records) {
      const old = await db.applications.get(rec.id);
      if (!old) {
        await db.applications.add(rec);
        added += 1;
      } else if (rec.updatedAt > old.updatedAt) {
        await db.applications.put(rec);
        updated += 1;
      }
    }
  });
  return { added, updated };
}
```

> 导入必须走事务，避免部分写入导致数据处于半残状态。`replace` 模式用 `clear + bulkPut` 包在同一个事务里。

### 6.2 表单 `ApplicationForm`

- 受控组件 + 本地 `errors` 状态，校验规则集中在 `validate(input)` 纯函数中，便于单测。
- `url` 字段在 `onBlur` 时立即规范化并回填到输入框，让用户看到最终保存的值。
- 提交时若 `url` 非空但 `normalizeUrl` 返回 `null`，阻断并提示「网址格式不正确，可留空」。
- 抽屉关闭前比对初始值与当前值，有变更则弹二次确认。

```ts
export interface FormErrors {
  company?: string;
  role?: string;
  url?: string;
  appliedAt?: string;
}

export function validateForm(input: {
  company: string;
  role: string;
  url: string;
  appliedAt: string;
}): FormErrors {
  const errors: FormErrors = {};
  if (!input.company.trim()) errors.company = "请填写公司名称";
  if (!input.role.trim()) errors.role = "请填写岗位名称";
  if (input.url.trim() && !normalizeUrl(input.url)) errors.url = "网址格式不正确，可留空";

  const tomorrow = new Date();
  tomorrow.setDate(tomorrow.getDate() + 1);
  if (input.appliedAt > tomorrow.toISOString().slice(0, 10)) {
    errors.appliedAt = "投递日期不能晚于今天";
  }
  return errors;
}
```

### 6.3 删除撤销

```ts
type PendingDelete = { record: Application; timer: number };

const [pending, setPending] = useState<PendingDelete | null>(null);

async function handleDelete(record: Application) {
  await deleteApplication(record.id);
  const timer = window.setTimeout(() => setPending(null), 5000);
  setPending({ record, timer });
}

async function handleUndo() {
  if (!pending) return;
  clearTimeout(pending.timer);
  await restoreApplication(pending.record);
  setPending(null);
}
```

> 撤销的本质是"立即删除 + 内存暂存原对象 + 点击时 put 回去"，比软删除字段（`deletedAt`）更简单，且不会让数据表里堆积垃圾。

## 7. 关键工程约定

| 约定 | 说明 |
| --- | --- |
| 时间存储 | `appliedAt` 存 `YYYY-MM-DD` 字符串（避免时区偏移导致日期跳变）；`createdAt`/`updatedAt` 存毫秒时间戳 |
| ID 生成 | 一律 `crypto.randomUUID()`，不使用自增数字，方便导入合并 |
| 空值规范 | 可选字符串统一存 `undefined` 而非 `""`，导出时再转空字符串 |
| 排序稳定性 | 任何排序都必须有第二排序键（`createdAt`），否则同日记录顺序会抖动 |
| 组件职责 | 组件不直接调用 `db.applications`，统一走 `db/index.ts` 暴露的仓储函数 |
| 类型边界 | 读取外部数据（导入文件、剪贴板）必须先经过校验函数，禁止直接 `as Application` |

## 10. 已知坑位

1. **IndexedDB 按 origin 隔离**。`localhost:5173` 与 `127.0.0.1:5173` 是两个不同的 origin，数据不互通。始终用同一个地址访问，并在 `vite.config.ts` 里把 dev 与 preview 的端口都固定为 5173。
2. **无痕模式**。无痕窗口关闭后 IndexedDB 会被清除，不要在里面录数据。
3. **清缓存**。用户在浏览器里「清除浏览数据 → Cookie 及其他网站数据」会连 IndexedDB 一起清掉。因此导出按钮必须显眼，且在记录数超过 20 条时首次进入弹一次「记得定期导出备份」的提示。
4. **Tailwind 动态类名**。`bg-${tone}-50` 这类拼接不会被扫描到，必须用完整类名的映射表。
5. **中文排序**。`localeCompare` 必须传 `"zh-CN"`，否则按 Unicode 码位排序，结果反直觉。
6. **Dexie 版本升级**。修改索引字段时必须新增 `this.version(2).stores({...})`，不能原地改 v1，否则老用户数据库不会升级。
