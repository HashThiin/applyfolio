## 二、状态流程重构（需求 5）

新的状态枚举，按校招真实流程排列：

```
投递 → 简历初筛 → 测评 → AI面 → 笔试 → 群面 → 面试 → Offer
```

外加两个终止态：`已挂`、`已放弃`。

| value | 标签 | 色调 |
|---|---|---|
| applied | 投递 | blue |
| screening | 简历初筛 | blue |
| assessment | 测评 | violet |
| ai_interview | AI面 | violet |
| written | 笔试 | amber |
| group_interview | 群面 | amber |
| interview | 面试 | amber |
| offer | Offer | emerald |
| rejected | 已挂 | slate |
| withdrawn | 已放弃 | slate |

- **状态切换方式**：手动点击列表行状态徽章选择，新建默认为「投递」。
- **自动推进**：编辑一条仍处于「投递」的记录并保存时，若未手动改动状态，会自动进入「简历初筛」（toast 会提示）；若你已手动选了其他状态，则尊重你的选择，不覆盖。
- **统计口径不变**：`进行中 = 总数 − Offer − 已挂 − 已放弃`。
- 旧值（applied/written/interview/offer/rejected/withdrawn）全部是新值子集，**历史数据不会丢失**。

## 三、多岗位录入（需求 1）

- 数据模型保持「一行 = 一个公司 + 一个岗位」，无需改表结构。
- 新增表单：`岗位名称` 支持多行，默认 2 行，可点「添加岗位」继续增加，多余行可删除。
- 保存时：公司/网址/日期/渠道/颜色/状态 为共享信息，**每个非空岗位各创建一条记录**，之后可分别推进各自的状态。
- 编辑单条记录时：只显示该记录自己的一个岗位（不展示多行增删）。

---

## 四、题目记录入口调整（需求 4）

- 删除旧的 `QuestionDrawer`（独立抽屉）与列表行上的「题目」按钮。
- 新增 `QuestionPanel`：把题目增删、图片上传、大图预览等能力内嵌进「编辑投递」抽屉底部。
- 打开任意记录的「编辑」即可直接看到并维护题目，操作更集中。
- **注意**：题目依赖已存在的投递记录（外键 application_id），因此**新建记录需先保存一次**，再进入编辑添加题目。

## 五、上线操作（必读）

1. **执行数据库迁移**（Supabase SQL Editor 运行，或在已配置的项目上）：
   ```sql
   -- supabase/migrations/003_status_pipeline.sql
   ALTER TABLE applications DROP CONSTRAINT IF EXISTS applications_status_check;
   ALTER TABLE applications
     ADD CONSTRAINT applications_status_check CHECK (
       status IN ('applied','screening','assessment','ai_interview',
                  'written','group_interview','interview','offer',
                  'rejected','withdrawn')
     );
   ```
   全新安装则 001 建表脚本已同步为新流程，无需再跑 003。

2. **重新部署**：
   ```powershell
   cd d:\job\app; vercel --prod --yes
   ```
   或在 GitHub 推送后由 Vercel 自动构建。
