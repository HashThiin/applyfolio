## 7. 覆盖缺口与残余风险

| 缺口 | 风险等级 | 原因 | 建议 |
|---|---|---|---|
| 无行覆盖率统计 | 中 | 未安装 `@vitest/coverage-v8` | 加一条依赖，`vitest run --coverage`，目标：纯函数 100%、整体 ≥40% |
| 仓储层零测试 | 中 | `db/applications.ts`、`db/questions.ts` 直连 Supabase | 引入 `__mocks__/@supabase/supabase-js` 做契约测试 |
| 无组件测试 | 中 | 未引入 Testing Library | 优先覆盖 `ApplicationForm` 校验与 `QuestionPanel` 媒体处理 |
| 无 E2E | 高 | 需真实账号与浏览器 | 至少补 1 条 Playwright 冒烟：登录 → 新增 → 改状态 → 刷新仍在 |
| 无 RLS 黑盒验证 | 高 | 无第二账号 | 用两个账号交叉读写，确认越权被拒 |
| 无生产响应头实测 | 中 | 网络不可达 | 部署后用外部扫描工具跑一次 |
| 未测 Safari / iOS | 中 | 无设备 | 至少验证 PWA 安装与 localStorage 受限场景 |
| 无并发/压测 | 低 | 个人规模 | 多用户前补 |

**结论**：自动化层足以保证"代码能编译、纯函数逻辑正确、构建产物可信、依赖无已知漏洞"；**不足以保证"业务链路在真实环境可用"**。后者的第一道防线是第 5.6 节用例矩阵。
