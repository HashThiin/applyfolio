## 二、第 1 项：逐岗位独立网址

数据层本来就符合要求——`applications` 一行一岗位，`url` 就在行上（同一公司多个岗位 = 多条记录）。真正的问题在**表单**：只有一处共享「岗位网址」输入框，提交时把同一个网址写给该公司的每个岗位。

改动：

- `src/features/applications/formSchema.ts`
  - 新增 `RoleDraft { name: string; url: string }`；`Draft` 由 `role: string` + `url: string` 改为 `roles: RoleDraft[]`。
  - 校验改为逐行：任何一行填了网址就要能 `normalizeUrl`，否则报「第 N 行网址格式不正确，可留空」；岗位名只需至少一行非空。
- `src/features/applications/ApplicationForm.tsx`
  - `emptyRole()` / `createEmpty()` 默认给两行空岗位；`toDraft(record)` 把既有记录包成一行（`{ name: record.role, url: record.url ?? '' }`）。
  - `toInputs` 逐岗位映射 `url: role.url ? normalizeUrl(role.url) : null`，因此每个岗位各自写自己的 `url`。
  - 编辑区「岗位名称」+ 独立「岗位网址」两个字段合并为**「岗位与网址」**区块：每行一张 `rounded-lg border border-ink-200/80 bg-white p-2.5` 卡片，内含岗位名输入、删除按钮（至少留一行）与该行网址输入（`aria-label="第 N 行岗位网址"`，占位「该岗位的招聘页网址（可选，自动补 https://）」）。
  - `dirty` 判定改为逐行比较 `name` 与 `url`，避免改了某行网址却不触发「未保存」提示。

效果：一个公司下 A 岗、B 岗各存各的链接，列表按行「打开网址」直接到对应岗位页——这是后续「按岗位抓 JD 做 AI 建议」的前置数据位。

## 三、第 2 项：编辑区颜色 = 列表观感

根因：列表头像用的是 `color-mix(in srgb, <color> 15%, var(--color-page))` 的浅色内核（外侧再压 1px 进度条），而编辑区色块画的是**纯色实心**，于是「选的时候鲜艳、回到列表发白」。

改动：

- 新增 `src/lib/color.ts`，把观感抽成唯一来源：
  ```ts
  export function avatarTint(color: string): string {
    return `color-mix(in srgb, ${color} 15%, var(--color-page))`
  }
  ```
- `src/components/CompanyAvatar.tsx` 与 `ApplicationForm.tsx` 共用它。编辑区色块改为 `rounded-full` + `backgroundColor: avatarTint(c.value)` + `borderColor: c.value` + 选中 `ring-2`（环色同为纯色），hex 圆点同样「混色底 + 纯色描边」，色板下方提示改为「与列表头像同一色阶，选中所见即列表观感」。
