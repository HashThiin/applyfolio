# 【重要 · 影响正常运行】热修 · 2026-10-24 01:13

> 🔴 **优先级：P0 · 必须部署**。不修这个的话，刷新/冷启动会偶发“首屏空列表”且需多次刷新才能恢复。

> 症状：偶发刷新后列表空，多刷两次又出现。
> 根因：冷启动 session 恢复与 useAllApplications 首屏查询存在竞态。

---

## 一、根因分析

`MainApp` 之前这样取用户 ID：

```tsx
const [uid, setUid] = useState<string>('')          // ← 首帧空串
useEffect(() => {
  supabase.auth.getSession().then(({ data: { session } }) => {
    if (session?.user) setUid(session.user.id)      // ← 异步回填
  })
}, [])

const { data } = useAllApplications({ userId: uid })
```

同时 `useAllApplications` 的 effect **不判空**，会在挂载微任务里立刻以 `''` 发一次查询：

```tsx
useEffect(() => {
  void Promise.resolve().then(() => refresh())  // userId = '' → RLS 过滤 → 0 行
  ...
}, [refresh])
```

**时序**：
1. MainApp 挂载 → `uid = ''`
2. useAllApplications effect 微任务里发查询 → **返回空列表 → 触发空态**
3. `getSession()` resolve → 真正 uid 落地 → refresh 依赖变化 → 再拉 → 数据回来

**为什么"多刷两次才有"**：
- supabase-js 把 session 存 localStorage。冷启动第一次要等 storage hydrate，`getSession()` 慢一帧 → 触发上面的空档。
- 第二次刷新时 storage 已热，getSession 几乎同步 resolve → 首屏就带正确 uid。
- 若 access token 过期（1h 有效期），supabase 自动 refresh；若刚好赶上你 F5，第一次拿旧 token 会被 RLS 挡，第二次才正常。
- 叠加 PWA 的 Service Worker 首次激活需一次 reload，容易让用户误以为是"要刷两次"。

---

## 二、修复

### 1) AuthGuard 直接把 session 中的 userId 通过 Outlet context 交给子路由

```tsx
// src/features/auth/AuthGuard.tsx
return <Outlet context={{ userId: session.user.id }} />
```

### 2) MainApp 从 outlet context 同步读 uid，不再走异步 getSession

```tsx
// src/features/MainApp.tsx
import { useNavigate, useOutletContext } from 'react-router-dom'

const navigate = useNavigate()
const { userId: uid } = useOutletContext<{ userId: string }>()
```

删除：本地 `useState<string>('')` + `useEffect(getSession)`。

### 3) useAllApplications 加"userId 未就绪就不查"的兜底

```ts
useEffect(() => {
  if (!userId) {
    void Promise.resolve().then(() => setLoading(false))
    return
  }
  void Promise.resolve().then(() => refresh())
  const channel = supabase.channel('applications-realtime')...
  return () => supabase.removeChannel(channel)
}, [refresh, userId])
```

---

## 三、影响

- 冷启动首屏不再出现"空列表 → 数据回来"的闪一下。
- 已登录用户刷新：`uid` 从 AuthGuard 到 MainApp 是同步传递的，没有中间态。
- 兜底的判空也挡住任何未来引入的空 uid 触发查询。
